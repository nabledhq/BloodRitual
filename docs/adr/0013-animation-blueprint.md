# 0013. An Animation Blueprint built by script, with upper-body montages

Status: Accepted

## Context

Until now the Protagonist played one animation asset at a time: C++ picked a
blend space or clip each tick and swapped it on a single-node instance
(ADR 0011). That had two costs, which ADR 0012 listed as known limitations:

* Every switch cut abruptly.
* Swings, shots and reloads were full-body clips, so he had to stand still to
  fight.

The project builds its content with scripts so that it can be rebuilt and
reviewed (ADR 0011). An Animation Blueprint's graph is normally drawn by hand
in the editor. However, UE 5.8 exposes graph editing to editor Python through
`unreal.BlueprintGraphEditor` (the API behind the engine's experimental
Editor toolset), and that API works on AnimGraphs. It can create nodes, connect
pins, set pin values and import a node's settings as text.

## Decision

* **`UBloodRitualProtagonistAnimInstance`** (C++, `Characters/`) is the
  parent class. Each update it reads the character into plain variables:
  * `GroundSpeed`;
  * `bFalling`, `bCrouched` and `bDead`;
  * `bArmed` and `bRanged`;
  * `AimWeight`, eased between 0 and 1.

  It holds no logic beyond that.
* **`ABP_Protagonist`** is generated by `scripts/editor/build_anim_blueprint.py`.
  Its graph is:
  * **Locomotion:** the unarmed, melee, ranged or crouched blend space,
    chosen by the bools with 0.2 s blends. While falling the jump loop takes
    over (0.15 s in, 0.1 s out on landing). The aiming pose is layered above
    `spine_01`, weighted by `AimWeight`.
  * **Upper body:** an `UpperBody` slot, layered above `spine_01` over
    locomotion.
  * **Full body:** the `DefaultSlot` slot over everything.
  * **Death:** the death clip once `bDead`.

  Re-running the script rebuilds the graph in place.
* **One-shot clips are dynamic montages** played by the character
  (`PlaySlotAnimationAsDynamicMontage`):
  * **Upper body:** swings, shots, reloads and flinches. They no longer lock
    movement, and moving does not cancel them.
  * **Full body:** the roll, the jump take-off and landing, searching and
    depositing. These keep their movement lock, and moving cancels them as
    before.

  `UpperBody` is registered on the skeleton in a slot group of its own, so its
  montages do not stop full-body ones. Python cannot reach a skeleton's slot
  groups, so `UBloodRitualEditorScripting::AddAnimSlot` does this.
* **Locomotion is built twice:** once as the base pose and once as the source
  of the `UpperBody` slot. The scripting API cannot name a cached pose, so
  the two branches cannot share one. Both copies get identical inputs every
  frame, so they produce the same pose. The cost is evaluating locomotion
  twice for one character.

## Consequences

* He can swing, shoot, reload and flinch while walking or running. Weapon
  changes, crouching, jumping, landing, aiming and dying blend instead of
  cutting.
* The Animation Blueprint is 0.38 MB; content totals 48.6 MB of the 50 MB
  budget.
* The graph can be opened and edited in the editor like any Animation
  Blueprint. However, hand edits are lost the next time the script runs, so
  changes belong in the script.
* `import_protagonist.py` rebuilds `Content/Characters/Protagonist` from
  scratch, so `build_anim_blueprint.py` runs after it.
* The infected still use single-node animation; moving them onto an Animation
  Blueprint belongs with the AI ticket (ADR 0003).
* Still missing: turn-in-place, aim offsets (he aims along the camera's yaw
  only), and foot IK.
